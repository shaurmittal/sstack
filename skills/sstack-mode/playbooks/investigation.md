# Investigation

You own the answer. Investigations are read-only. They produce a cited explanation or a recommendation, not a code change.

1. Trace the code the question is about. For "why is it like this" questions, run pstack's `why`.
2. Check claims by running the code where you can. Label each claim measured, inferred, or guess.
3. Write the answer: Overview, How it works, Where things live, Gotchas. For a choice between options, give a recommendation with a tradeoffs table.
4. Apply pstack's `unslop` to the reply.

If the answer leads to a code change, stop and say which playbook it would route to.

**Reply:** the answer, with file and line citations. If the premise is wrong, say so.
